# 홈 첫 대화 예시 변경안

계획: delivery-37836516fc64deceb4c5003bde28d186.
프로젝트: maldongmu.
기준 revision: 95c9196554275687a46d9f7a7646fb7e318fe798.

이 산출물은 도구가 비활성화된 호출에서 작성한 변경 제안이다. 파일 적용, 테스트, 타입 검사, 빌드, 독립 리뷰, QA, 배포는 실행하지 않았다. PM 의견은 지정한 8개 파일의 착수 범위에만 반영했으며 완료 승인으로 해석하지 않았다.

## 제안 동작

홈 헤더 아래에 제목과 설명, 번역된 실제 예시 버튼 3개를 배치한다. 각 버튼의 표시 문장, data-prompt, 저장 문장과 send(text)에 전달하는 문장은 같다. 기존 sand·line·brown 토큰과 본문 폰트를 사용하고 제목에만 dot-title을 적용한다. 버튼은 세로 배치, 최소 높이 44px, 자연 줄바꿈, focus-visible 외곽선을 갖는다. 기존 coral CTA를 유지한다.

클릭 즉시 ref 잠금을 설정해 연속 클릭의 대화 생성을 막는다. 이미 불러온 featured 첫 사람을 선택하며, 없으면 기존 GET /personas/random을 사용한다. 기존 POST /conversations 성공 뒤에만 문장을 저장하고 id만 포함한 /chat/{id}로 이동한다. 조회·생성 실패는 다시 시도할 수 있는 번역된 오류를 표시한다. LoginRequiredError는 기존 홈 LoginSheet를 연다.

초안은 대화 id별 sessionStorage에 5분간 보관한다. 최대 2000자이며 빈 문장과 공백 문장은 거부한다. 저장소 접근이나 쓰기가 막히면 같은 문서 내 클라이언트 이동에 한해 메모리로 전달한다. 메모리 폴백은 전체 새로고침이나 다른 문서로 이동하면 보존되지 않는다. URL, query, hash, history state에 문장을 넣지 않는다.

채팅은 인사말 로드를 포함한 기존 초기 로드가 끝나고 persona가 있으며 기존 전송이 진행 중이지 않을 때 초안을 한 번 소비한다. 이 effect는 현재 렌더의 send 클로저를 사용한다. 초안은 전송 전에 삭제하고 ref로 effect 반복을 막는다. 정상 sessionStorage 경로에서는 새로운 모듈 인스턴스에서도 소비한 초안을 다시 읽지 못한다. 삭제만 실패하면 빈 값으로 덮어쓰고, 읽을 수 있는 저장값을 삭제·덮어쓰기 모두 할 수 없다면 중복 방지를 위해 자동 전송하지 않는다.

전송은 기존 send(text)를 그대로 사용한다. 로그인·한도 오류 시 기존 LoginSheet·QuotaSheet와 입력 문장 복원이 동작하도록 유지한다. 오류가 나도 자동 재전송하지 않는다. 기존 입력창에 company-message-input test id만 추가한다. 서버, lib/api, 인증, 게스트 한도, 결제, 의존성·설정과 pickLang·translate 로직은 변경하지 않는다.

## 제안 검사와 인계

실행기는 적용 전 기준 SHA, 원문 SHA-256, 기존 변경과 최신 원격 main을 확인해야 한다. 기존 파일은 각 before가 정확히 한 번 존재하고 치환끼리 겹치지 않을 때만 적용한다. 변경 범위는 계획의 8개 파일로 제한한다.

새 순수 회귀 테스트는 기존 TypeScript로 초안 모듈만 메모리에서 CommonJS로 변환해 VM에서 평가한다. 저장소와 시간을 주입하며 앱·API·브라우저를 로드하지 않는다. 정확한 문장 보존, 한 번 소비, 새 인스턴스 재소비 방지, 다른 id, 만료 경계, 빈 값, 길이 제한, 저장소 예외와 삭제 실패를 검사하도록 제안한다.

등록된 node --test apps/web/test/*.test.cjs, TypeScript noEmit, Next production build를 실행하고 실제 결과를 적용 후 고정 커밋에 묶어야 한다. 실행기가 셸 없이 인자를 전달한다면 테스트 glob을 실제 파일 목록으로 확장해야 한다. 이번 제안에는 실행 결과가 없다.

독립 리뷰와 QA에는 고정 커밋 및 실제 검사 증거를 전달한다. 브라우저 QA는 backend 쓰기를 모의 처리하고, 360·768·1280px, 200% 확대, en·ja, 키보드와 상태 안내, 연속 클릭, 인사말 뒤 정확한 문장 1회 자동 전송, Strict Mode·재마운트·새로고침·뒤로/앞으로 이동, featured 유무, 조회·생성 실패와 로그인·한도를 확인해야 한다. 직접 입력·IME·중지·초대·그룹 주제·호감도·신고 회귀도 확인해야 한다. 모의 backend 결과는 실제 API나 유료 모델 검증이 아니다.

구현자는 자기 변경의 독립 리뷰·최종 QA를 승인하지 않는다. 이후 고정 커밋 preview 화면 증거, 최신 main 비교와 통합, production 배포 SHA 및 운영 URL 화면 증거가 필요하다. 새 변경이 있으면 영향받는 검증을 다시 받아야 한다. 이 문서는 배포나 완료를 증명하지 않는다.
